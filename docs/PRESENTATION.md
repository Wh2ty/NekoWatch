## Слайд / блок 1 — Проблема (≈1:00)

Добрый день. Мы представляем проект **NekoWatch** — анализатор security-алертов
в формате **Wazuh** для работы в контуре **SOC**.

В современной инфраструктуре конечные точки, серверы и сетевые устройства
постоянно генерируют события безопасности. Система вроде Wazuh собирает их и
превращает в **алерты** — сообщения о подозрительной активности: неудачный
вход, аномальный перевод, сканирование портов и т.д.

Проблема аналитика: за минуту могут прийти десятки и сотни записей. Читать
сырой файл глазами невозможно. Нужен контур: **принять поток → понять →
отфильтровать → сгруппировать → принять решение**.

NekoWatch как раз закрывает этот контур в учебном и прикладном виде.

---

## Слайд / блок 2 — Что умеет система (≈1:00)

*Показать дашборд `/`.*

NekoWatch:

1. **Слушает** файлы алертов Wazuh или демо-генератор Logener.  
2. **Парсит** JSON (и текстовый `alerts.log`).  
3. **Нормализует** поля: время, уровень, IP, пользователь, правило.  
4. **Обогащает** картой **MITRE ATT&CK**.  
5. **Пишет** в SQLite батчами с поиском и индексами.  
6. Отдаёт **дашборд**, REST API, **WebSocket** live-ленту, корреляцию,
   triage и экспорт.

Для реального Wazuh пути задаются не в коде, а в файле
`config/sources.yaml`:  
`/var/ossec/logs/alerts/alerts.json`, `alerts.log`,
`/var/ossec/logs/archives/archives.json`.

## Слайд / блок 3 — Живой поток (≈1:30)

*Открыть `/logener`, запустить генератор; вернуться на панель.*

Сейчас мы имитируем поток алертов. В шапке растут метрики:

- **Соб/с (EPS)** — сколько событий принято за последнюю секунду;  
- **В БД** — сколько уже сохранено;  
- **Очередь** — не отстаёт ли запись;  
- зелёный индикатор — живой **WebSocket**.

Справа — «прямой эфир»: алерты появляются без перезагрузки страницы.
Это важно для SOC: реакция должна быть близка к реальному времени.

---

## Слайд / блок 4 — Аналитика и фильтры (≈1:30)

*Показать KPI и графики; применить фильтр high/critical.*

Ниже — операционная картина:

- распределение по **критичности**;  
- события **во времени**;  
- топ правил и IP;  
- тактики **MITRE ATT&CK**.

Все фильтры — единая выборка: изменили период или IP — обновились и графики,
и таблица, и экспорт. Аналитик не сравнивает «разные правды» в разных виджетах.

Severity у нас выводится из Wazuh `rule.level`: чем выше уровень правила, тем
серьёзнее событие для очереди разбора.

---

## Слайд / блок 5 — Работа аналитика (≈1:30)

*Triage, brute-force, группы; опционально GigaChat.*

Таблица алертов — рабочее место:

- отмечаем строки и меняем статус triage: «в работе», «закрыт», «ложное»;  
- ищем **brute-force** скользящим окном;  
- смотрим **скоррелированные группы** повторов;  
- при наличии ключа **GigaChat** просим ИИ связать события и дать рекомендации.

ИИ здесь — помощник, а не судья. Решение остаётся за человеком.

---

## Слайд / блок 6 — Как устроено внутри (≈1:00)

Стек:

- **FastAPI** + **uvicorn** — асинхронный HTTP/WebSocket API;  
- **SQLAlchemy 2.0 asyncio** + **aiosqlite** + SQLite WAL — хранилище;  
- **Pydantic** — строгие модели входных алертов;  
- **aiofiles** — неблокирующее чтение хвоста файла;  
- Jinja2 + Chart.js — дашборд без тяжёлого фронтенд-бандлера.

Почему **aiosqlite** обязателен: async-движок SQLAlchemy для SQLite умеет
говорить с БД только через этот драйвер. Синхронный `sqlite3` заблокировал бы
event loop и «заморозил» API под нагрузкой.

Надёжность: offset файла пишется в БД **в одной транзакции** с батчем алертов —
после сбоя мы не «теряем» принятое и не оставляем дыру в checkpoint без данных.

---

## Слайд / блок 7 — Итог (≈0:30)

NekoWatch показывает полный мини-контур SOC над алертами Wazuh: от файла логов
до метрик, корреляции и решения аналитика — с прозрачной архитектурой на
современном async Python и возможностью подключить реальные пути
`/var/ossec/...` через один YAML.

Спасибо. Готовы к вопросам.

# Глоссарий для комиссии

## SOC и кибербезопасность

| Термин | Простыми словами |
| --- | --- |
| **SOC** | Security Operations Center — команда мониторинга и реагирования на угрозы |
| **SIEM** | Система сбора и корреляции логов безопасности (Splunk, Elastic SIEM, Wazuh…) |
| **XDR** | Расширенное детектирование и реагирование сразу по многим типам телеметрии |
| **Wazuh** | Открытая платформа агентского мониторинга + менеджер правил/алертов |
| **Алерт** | Запись «правило сработало»: уровень, описание, хост, IP, пользователь |
| **Agent** | Программа на хосте, которая шлёт логи/события на менеджер Wazuh |
| **Rule / rule.level** | Правило детекта и его «тяжесть» (0–15 у Wazuh) |
| **Severity** | Наша укрупнённая шкала: low / medium / high / critical |
| **Triage** | Очередь разбора алертов аналитиком (новый → в работе → закрыт / ложное) |
| **False positive** | Ложное срабатывание — событие не является реальной угрозой |
| **Корреляция** | Связывание нескольких событий в один осмысленный инцидент |
| **Brute-force** | Перебор паролей: много неудачных входов за короткое время |
| **MITRE ATT&CK** | Справочник тактик и техник реальных атак (T1110 = Password Brute Force и т.п.) |
| **Tactic / Technique** | «Зачем» атакующий действует / «как» конкретно он это делает |
| **IoC** | Indicator of Compromise — признак компрометации (IP, хеш, домен) |
| **EPS** | Events per second — скорость потока событий |
| **NDJSON** | newline-delimited JSON: по одному JSON-объекту на строку файла |
| **FTS** | Full-text search — полнотекстовый поиск по сообщениям |
| **Checkpoint / offset** | Смещение в файле: «досюда уже прочитали» |
| **WAL** | Write-Ahead Logging — режим SQLite для быстрых параллельных чтений/записей |
| **Backpressure** | Когда писатель не успевает, читатель замедляется, а не теряет данные |
| **WebSocket** | Двусторонний канал браузер↔сервер без постоянных HTTP-опросов |
| **ECS** | Elastic Common Schema — единая схема полей для security-событий |
| **RBAC** | Role-Based Access Control — права по ролям |

## Библиотеки и понятия «выше базового Python»

| Технология | Зачем в проекте |
| --- | --- |
| **FastAPI** | Современный веб-фреймворк: маршруты, валидация, OpenAPI из типов |
| **uvicorn** | ASGI-сервер, на котором крутится FastAPI |
| **ASGI / async / await** | Модель «не блокируем поток, пока ждём диск/сеть» — много клиентов сразу |
| **Pydantic / pydantic-settings** | Валидация JSON-алертов и конфиг из env/`.env` |
| **SQLAlchemy 2.0** | ORM + Core SQL: модели таблиц, безопасные запросы, агрегации |
| **aiosqlite** | Async-драйвер SQLite для SQLAlchemy; **нужен**, пока URL = `sqlite+aiosqlite` |
| **aiofiles** | Async-чтение/запись файлов (хвост логов) |
| **Jinja2** | Серверный HTML из шаблонов |
| **PyYAML** | Чтение `config/sources.yaml` |
| **httpx / pytest / pytest-asyncio** | Тесты HTTP API и async-кода |
| **gigachat (SDK)** | Клиент к LLM Сбера для ИИ-разбора алертов |
| **Chart.js** | Графики на дашборде в браузере |
| **Protocol (typing)** | Контракт репозитория: можно заменить SQLite, не ломая сервисы |
| **Dependency injection (container)** | Один объект собирает БД, ingestion, сервисы при старте приложения |

### Одна фраза «если спросят про aiosqlite»

> Мы пишем в SQLite **асинхронно** через SQLAlchemy. Диалект называется
> `sqlite+aiosqlite`, и пакет **aiosqlite** — его драйвер. Убрать его нельзя,
> не переписав хранилище на синхронный режим или другую СУБД.
