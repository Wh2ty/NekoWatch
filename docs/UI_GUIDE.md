# Руководство по интерфейсу NekoWatch

Описание элементов SOC-панели (`/`) и страницы генератора (`/logener`).
Все фильтры влияют и на таблицу, и на графики, и на экспорт — одна выборка.

---

## Верхняя панель (header)

| Элемент | За что отвечает |
| --- | --- |
| **NekoWatch / версия** | Название продукта и номер сборки |
| **Панель / Генератор / API** | Навигация: дашборд, Logener, OpenAPI |
| **Темы** (Тёмная / Трава / Закат) | Переключение CSS-темы оформления |
| **Индикатор «подключение…»** | Состояние WebSocket live-канала (зелёный = online) |
| **Соб/с** | Events Per Second: сколько событий принято **за последнюю 1 секунду** |
| **В БД** | Общее число алертов, уже сохранённых в SQLite |
| **Очередь** | Глубина внутренней очереди ingestion (backpressure) |
| **Ошибки** | Число строк, которые парсер не смог разобрать |

Баннер **«Демо-режим»** появляется, если на Генераторе включён учебный сценарий
(флаг в `localStorage`, не данные из БД).

## Блок «Нейросеть · GigaChat»

| Элемент | Назначение |
| --- | --- |
| **Анализировать** | Отправляет текущую выборку алертов в GigaChat: корреляция цепочек + рекомендации аналитику |
| **Корреляция** | Текстовый разбор возможных связанных событий / kill chain |
| **Рекомендации** | Практические действия SOC (изоляция, сброс пароля, проверка хоста и т.п.) |
| **Исходный JSON** | Сырой ответ модели для отладки |

Нужны учётные данные в `.env` (`GIGACHAT_CREDENTIALS`). Без ключа блок покажет ошибку API.

## Блок «Графики и метрики»

### KPI-карточки

| KPI | Смысл |
| --- | --- |
| **События** | Число алертов в текущем фильтре / окне |
| **Критические** | Severity `critical` (обычно rule.level 12–15) + сколько из них ещё «открыты» в triage |
| **Высокие** | Severity `high` (level 8–11) |
| **IP источников** | Уникальные `src_ip` в выборке |
| **Пользователи** | Уникальные учётные записи в выборке |
| **Правила** | Уникальные `rule_id` |
| **С флагом mail** | Алерты, помеченные Wazuh как требующие почтового уведомления (часто level ≥ 7) |

Шкала severity в проекте: **0–3 low**, **4–7 medium**, **8–11 high**, **12–15 critical**.

### Графики

| График | Что показывает |
| --- | --- |
| **События в секунду** | Живой EPS по WebSocket (окно 1 с) — нагрузка пайплайна «прямо сейчас» |
| **Распределение по критичности** | Доли low / medium / high / critical в выборке |
| **События во времени** | Гистограмма числа алертов по интервалам (`Гистограмма`: авто / 1м / 5м / …) |
| **Топ-10 правил** | Какие `rule_id` срабатывают чаще всего |
| **Топ IP источников** | Откуда чаще всего идут события (часто внешние атакующие) |
| **Топ IP назначений** | Куда чаще целятся / на каких агентах события |
| **Тактики MITRE ATT&CK** | Распределение по тактикам (Initial Access, Credential Access, …) |
| **Топ пользователей** | Учётные записи, чаще всего фигурирующие в алертах |

## Блок «Фильтры»

| Поле | Назначение |
| --- | --- |
| **Период** | Быстрое окно: 15 мин … 7 дней или «всё время» |
| **Полнотекстовый поиск** | FTS5 по message / description / raw (с LIKE-fallback) |
| **Критичность** | Мультивыбор severity |
| **Статус triage** | `new` / `in_progress` / `resolved` / `false_positive` |
| **Техника / тактика MITRE** | Фильтр по ATT&CK ID |
| **ID правила / события** | Точный или частичный `rule_id` |
| **IP источника** | Фильтр по `src_ip` |
| **Уровень мин–макс** | Диапазон Wazuh `rule.level` (0–15) |
| **Гистограмма** | Шаг бакетов для таймлайна |
| **Экспорт CSV / JSON / ECS** | Выгрузка **той же** отфильтрованной выборки |
| **Применить / Сбросить** | Пересчитать графики и таблицу |
| **Изменение правил** | Модалка конструктора пользовательских правил корреляции |

## Блок «Мониторинг устройств»

| Элемент | Назначение |
| --- | --- |
| **Источники** | Карточки агентов/источников: таймаут «нет событий», статус |
| **Пользователи LAN** | Зарегистрированные станции / ping (мок или ICMP) |
| **Уведомления** | События монитора и срабатывания correlation rules |
| **+ Устройство** | Регистрация «своего» устройства |
| **Пинг / Обновить** | Принудительная проверка связности / refresh доски |

## Блок «Логи и прямой эфир»

### Таблица алертов

Колонки: время, уровень, критичность, правило, описание, источник, пользователь,
ATT&CK, статус triage. Чекбоксы + кнопки **В работе / Закрыть / Ложное** —
массовое обновление triage. Пагинация ‹ ›.

Клик по строке открывает детали (ECS + raw JSON) в drawer.

### Прямой эфир

WebSocket-лента новых алертов в реальном времени. **Пауза** останавливает
отрисовку, не останавливая ingestion на сервере.

### Brute-force

| Поле | Смысл |
| --- | --- |
| **Окно (сек)** | Скользящее окно поиска всплесков неудачных логинов |
| **Порог** | Минимум попыток в окне, чтобы считать инцидентом |
| **Найти** | Запуск детекции на **текущей** выборке |

### Скоррелированные группы

Группировка повторяющихся сигнатур (одно правило + похожий контекст): сколько
раз, первый/последний раз, длительность, число IP и пользователей.

## Страница «Генератор» (`/logener`)

Управление демо-потоком Logener (пишет NDJSON в файл из `sources.yaml` /
`NEKOWATCH_LOG_FILE`).

Типичные действия: старт/стоп генератора, скорость, демо-режим, **полный сброс**
БД и файла (с тройным подтверждением) — только для учебной среды.

---

## Источники данных для комиссии

- Демо: `active: [logener]` в `config/sources.yaml`.
- Реальный Wazuh: `active: [alerts_json]` (и при необходимости `alerts_log`,
  `archives_json`).
