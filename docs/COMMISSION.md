# План ознакомления для комиссии + возможные вопросы

## Цель показа (15–20 минут с запасом)

Показать, что NekoWatch — рабочий **учебный/прикладной SOC-анализатор** для
алертов Wazuh: приём потока → нормализация → хранение → аналитика → реакция
аналитика (triage) → опционально ИИ.

---

## Сценарий демонстрации (рекомендуемый порядок)

### 0. Подготовка (до входа комиссии, ~2 мин)

1. `pip install -r requirements.txt`
2. Убедиться, что в `config/sources.yaml` активен `logener` (для демо без
   Linux/Wazuh).
3. При необходимости положить ключ GigaChat в `.env`.
4. Запуск: `uvicorn app:app --host 127.0.0.1 --port 8000`
5. Открыть две вкладки: `/` и `/logener`.

### 1. Контекст продукта (1–2 мин)

- Проблема: поток security-алертов трудно читать «глазами».
- Решение: нормализованное хранилище + дашборд + корреляция + triage.
- Совместимость с форматом Wazuh; для защиты без сервера — Logener.

### 2. Источники логов (1 мин)

Показать `config/sources.yaml`: пути

- `/var/ossec/logs/alerts/alerts.json`
- `/var/ossec/logs/alerts/alerts.log`
- `/var/ossec/logs/archives/archives.json`

Объяснить: для реального Wazuh меняем `active`, перезапускаем сервис.

### 3. Генерация потока (2 мин)

На `/logener` запустить генератор. На панели показать рост **Соб/с**, **В БД**,
живой WebSocket-фид.

### 4. Аналитика (3–4 мин)

- KPI и графики severity / timeline / top rules / MITRE.
- Фильтр: например high+critical за последний час, IP или rule_id.
- Показать, что графики и таблица меняются синхронно.

### 5. Работа аналитика (3 мин)

- Выделить алерты → «В работе» / «Закрыть» / «Ложное».
- Brute-force с окном и порогом.
- Скоррелированные группы.
- При наличии ключа — «Анализировать» (GigaChat).

### 6. Техническая «начинка» (2 мин)

- FastAPI + async SQLAlchemy + **aiosqlite** (почему нужен).
- Checkpoint offset, батчи, WAL.
- Тесты: `pytest`.

### 7. Закрытие (1 мин)

Итог: от сырого лога Wazuh до решения аналитика в одном контуре.

## Потенциальные вопросы комиссии и короткие ответы

**Что такое SOC?**  
Security Operations Center — команда/процесс круглосуточного мониторинга
киберинцидентов, triage и реагирования.

**Чем отличается от SIEM?**  
SIEM — платформа сбора/корреляции логов. NekoWatch — узкий анализатор потока
Wazuh-алертов с дашбордом (учебный/прикладной контур, не полноценный Splunk).

**Почему Wazuh?**  
Открытый XDR/SIEM-агентский стек; алерты в JSON/`alerts.log` — стандартный
выход manager’а.

**Что такое MITRE ATT&CK?**  
База знаний тактик и техник атак. Мы маппим rule/groups → technique ID, чтобы
говорить на языке угроз, а не только «rule 5712».

**Зачем SQLite, а не Postgres/Elastic?**  
Для демо и одного узла достаточно встраиваемой БД: простой деплой, FTS5,
транзакции. Архитектура через `LogRepository` допускает замену бэкенда.

**Зачем aiosqlite?**  
SQLAlchemy async для SQLite работает только через драйвер `aiosqlite`. Иначе
синхронные вызовы блокируют event loop uvicorn.

**Как не теряются логи при падении?**  
Файл на диске — источник истины; offset checkpoint пишется после успешного
коммита батча (в одной транзакции с вставкой). После рестарта хвост
продолжается с checkpoint.

**Что такое EPS?**  
Events per second — мгновенная скорость приёма за последнюю секунду.

**Что такое triage?**  
Очередь разбора: new → in_progress → resolved / false_positive, с аудитом.

**Что делает GigaChat здесь?**  
LLM-помощник: связать алерты в гипотезу атаки и предложить действия. Не
заменяет правила и инженера.

**Безопасность демо?**  
Генератор и полный сброс — только для стенда. На проде — чтение реальных путей
Wazuh, без wipe. Контроль доступа (RBAC/токены на изменяющие эндпоинты) в
текущей версии не реализован — это открытый пункт на дальнейшую доработку,
а не готовая функция.

**Почему не Elasticsearch?**  
Возможен как следующий шаг; сейчас приоритет — прозрачный пайплайн и защита
без тяжёлой инфраструктуры.

**Как проверить корректность?**  
`pytest` + ручной сценарий: старт Logener → рост счётчиков → фильтр → triage →
экспорт.

**alerts.json vs alerts.log vs archives?**  
`alerts.*` — сработавшие правила (то, что обычно смотрит SOC). `archives` —
более полный архив событий. JSON удобнее для машинного разбора; `.log` —
классический текст (у нас есть парсер блоков `** Alert`).
